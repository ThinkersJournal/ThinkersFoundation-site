# What was found when the plan's VERIFY items were checked

Checked 2026-10-10 against the sources `PRE-FILING-PLAN.md` cites, for the PM. Not legal or tax advice.

**How reliable this is.** The pages were fetched through a tool that summarises each page with a small model, so
quotes are as returned, not byte-verified, and some pages (several `azcc.gov` and `about.us` URLs, two PDFs) could not
be read at all. Where a claim could not be checked it says COULD-NOT-VERIFY and is **not** confirmed. Anyone filing
should read the cited statute or page themselves; the links are the evidence, this table is only a pointer.

## Two things the plan should change, found while building

1. **SPF (plan 2.5 vs 2.1).** 2.1 says Email Routing adds the SPF record itself; 2.5 says to publish a null SPF.
   A domain with two SPF records fails every check (`permerror`). `plan.mjs` therefore publishes DMARC only and the
   runbook says to read what Cloudflare added and tighten **that** one.
2. **Hosting needs a decision the plan did not pose (item 10).** Git integration needs an org-owner click-through on
   GitHub and a dashboard step; Direct Upload does not but is irreversible. The runbook recommends Git integration and
   asks for the ruling; the site builds and tests the same either way.
